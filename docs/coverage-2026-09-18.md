### 7.2 顺带修掉的一个真 Bug（P0）

`core.CallLogWriter.log()` **持锁后调用会再次取锁的 `_flush_unlocked()`** —— `asyncio.Lock` 不可重入，
一旦缓冲达到 `max_buffer` 阈值即**永久死锁**（这正解释了该行历史上从未被覆盖：没有测试敢触发阈值）。
已改为先释放锁再 flush：

```python
async with self._lock:
    self._buffer.append(log_entry)
    reached_threshold = len(self._buffer) >= self._max_buffer
if reached_threshold:            # 锁外再 flush
    await self._flush_unlocked()
```

### 7.4 补测中踩到的坑（供后续复用）

**用假的 `asyncio.sleep` 给无限循环设预算时，预算必须按「延迟值」而非全局计数。**
`lifespan` 里 `CallLogWriter` 的 flush 循环 `await sleep(0)` 后**立即被重新调度**，因此在
`lifespan` 等待（线程化的）SQLite 调用期间它会**自旋**，把全局预算整块吃掉 —— 等 4 个维护
循环被创建时预算已耗尽，其函数体一行都不执行（覆盖率表现为「结构性永远缺失」，极易误判为不可达）。
改成 per-delay 预算后每个循环各拿到自己的额度，4 个循环体全部覆盖。

```python
class _SleepBudget:
    def __init__(self, per_delay: int = 4):
        self._per_delay = per_delay
        self._counts: dict[object, int] = {}
        self._real = asyncio.sleep

    async def __call__(self, delay, *args, **kwargs):
        if self._counts.get(delay, 0) >= self._per_delay:
            raise asyncio.CancelledError()
        self._counts[delay] = self._counts.get(delay, 0) + 1
        await self._real(0)
```
